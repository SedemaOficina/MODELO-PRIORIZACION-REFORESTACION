# Modelo de Priorización · Reforestación Urbana

Herramienta **"Modelo de priorización de reforestación urbana"** de la Secretaría del Medio Ambiente de la Ciudad de México · Sistema de Información Ambiental (SIA).

Mapa de consulta para que las 16 alcaldías y el Gobierno de la Ciudad identifiquen qué colonias, calles y vialidades primarias conviene reforestar primero, según el modelo de priorización del SIA. Incluye buscador único, ubicación del usuario en campo, descargas en Excel con diccionario de datos y fichas PDF por alcaldía, colonia, vialidades primarias, avenida y calle.

Esta carpeta es la **copia de trabajo oficial**: aquí vive la versión vigente, todo lo necesario para reconstruirla y la bitácora de decisiones.

**¿Vas a mantenerla o instalarla?** Empieza por [`ARQUITECTURA.md`](ARQUITECTURA.md): dónde está cada cosa, cómo se arma, formato de los datos y cambios comunes.

## Alcance

- **Solo de consulta:** no recibe reportes ni datos de los usuarios.
- **Sin datos personales:** la ubicación que usa "Mi ubicación" se queda en el teléfono; no se envía ni se guarda.
- **Lo que guarda el navegador:** una copia de los archivos de la propia herramienta (programa, estilos, datos, inventario de arbolado y tipografías), para abrir más rápido y sin conexión, y unas preferencias: si ya se leyó el aviso del modo ligero (`sia.avisoLigero`), la última alcaldía y red consultadas (`cp_inicio`, `cp_red`) y si ya se vio el recorrido guiado (`cp_recorrido`). Ninguna consulta ni dato del usuario.
- **Sitio estático:** no necesita base de datos, backend ni GeoServer. Lo único externo es el fondo satelital opcional de Esri, que se pide a su servidor solo si el usuario lo enciende (el fondo «Calles» es propio (manzanas del Catastro, parques, agua, ANP y AVA, en `datos/fondo/`, sin terceros ni claves)), y los enlaces a Google Maps de las tarjetas, que se abren en otra pestaña.

## Cómo reconstruir la herramienta

Después de cambiar cualquier archivo de `02_fuente/`:

```
python 02_fuente/construir.py
```

(En Windows, Python se llama `python`; en Linux o Mac, `python3`.)

Escribe `docs/`, `_local/priorizacion_reforestacion.html` y `05_documentacion/cifras_de_la_construccion.md`. Solo reescribe los archivos que cambiaron. Requiere únicamente Python 3. Si este README no nombra como vigente la versión que se construye, la construcción lo avisa.

La construcción **se detiene sin escribir nada** si falta o sobra un módulo, si un módulo está vacío o si los datos no son los registrados en `02_fuente/datos/SUMAS.json`. Los archivos de `docs/` que dejan de pertenecer al sitio no se borran: se mueven a `_to_delete/`.

Para verificar: `node 04_pruebas/correr_todas.js` (todo) o `node 04_pruebas/correr_todas.js rapidas` (solo lo que no abre el navegador). Cuántas pruebas son y cuánto tardan: `04_pruebas/LEEME.md`.

## Licencias y condiciones de terceros

- **Librerías** (deck.gl, pako, jsPDF, SheetJS): copias sin modificar, con el texto de cada licencia y su huella en `02_fuente/libs/` (ver `LICENCIAS.md`). **Tipografías** Cabin y Roboto: SIL Open Font License 1.1 (`02_fuente/fuentes/`).
- **Mapas de fondo:** «Calles» es un fondo propio, alojado con el sitio: manzanas del Catastro de la CDMX, parques y jardines del Inventario de Áreas Verdes 2017, ANP y AVA oficiales y cuerpos de agua (`03_procesamiento_datos/6_fondo.py` → `02_fuente/datos/fondo/`). Es el fondo con que abre la herramienta: de lejos pide solo parques, ANP y agua, y las manzanas, por alcaldía, al acercarse. No lleva crédito sobre el mapa (decisión de la v1.13). El satélite de Esri se usa sin clave y queda por regularizar con una clave de ArcGIS (`SIA_ESRI_KEY`); lleva en el mapa la atribución que pide Esri.
- **Pendiente de decisión institucional:** el repositorio no declara licencia para el código ni para los datos derivados; los términos de uso de la capa del índice de desarrollo social se confirman con su fuente (EVALÚA CDMX), y falta identificar el origen primario de los polígonos de colonias.

## Flujo de trabajo

1. Se edita en `02_fuente/`, se reconstruye y se corren las pruebas.
2. Cada versión es un commit, con un resumen y una descripción en español. Se revisa en GitHub Desktop (pestaña History) y se publica con **Push origin**. GitHub Pages se actualiza en uno o dos minutos.
3. Cada cambio se documenta en `05_documentacion/bitacora/`.
4. No se borran archivos de la carpeta: lo que sobre se mueve a `_to_delete/` para eliminarlo después.
5. **Git sobre la carpeta sincronizada por OneDrive:** si una orden de Git deja archivos de bloqueo (`.git/index.lock`, `tmp_obj_*`) que impiden el siguiente commit, se retiran moviéndolos a `_to_delete/`; las consultas se hacen con `GIT_OPTIONAL_LOCKS=0`. Solo una sesión trabaja sobre la carpeta a la vez.
6. **Verificación automática en GitHub:** en cada *Push*, GitHub repite las verificaciones rápidas y marca el commit con una palomita verde o una cruz roja (`.github/workflows/verificar.yml`). Qué hacer si falla: `05_documentacion/verificacion_automatica_github.md`. La página se publica igual; la cruz es un aviso para corregir.

## Navegadores y enlaces

- **Teclado:** Tabulador recorre los controles; Entrar o barra espaciadora activan los renglones de los listados; Esc cierra la ficha, el panel de capas y la ayuda.
- **Navegadores mínimos:** Chrome o Edge 80, Firefox 79, Safari 15, o posteriores, con WebGL 2 disponible. Si falta, la herramienta lo dice al abrir en lugar de quedar en blanco.
- **La consulta va en la dirección:** `?a=` clave de la alcaldía, `?c=` colonia, `?v=` avenida, `?r=gc` o `?r=both` para quién atiende, `?b=con` o `?b=sin` para el filtro de banqueta y `?e=` para el filtro «Espacio» (`cv` cepa vacante, `to` tocón, `am` árbol muerto; varios, separados por comas: `e=cv,to`). La dirección se puede compartir; Atrás y Adelante recorren las consultas.
- `?modo=ligero` y `?modo=completo` fuerzan el modo de dibujo. `#nomap` solo tiene efecto en las pruebas automáticas.
